# 里程碑

## 当前迭代

协议 2（2026-11-16）让语音输入等同于键盘输入。转写是中转服务的旁路，只返回文字、
不保存任何内容；草稿留在编写它的客户端（设备 RAM，上限 140 字并显示字数；网页
页面内存）。发送时携带完整文字，新会话由第一次发送创建并命名，因此不会出现空会话，
中转服务和 Hermes 也无需回收。设备与网页之间的草稿不再同步。设备未发送的草稿
不推迟休眠，深度睡眠或重启会丢失草稿。网关 SQLite 升级为结构 v4，不做
迁移。服务端测试、固件宿主测试和界面预览覆盖本次改动。实机（d6eb351）上重录、
第一次发送创建会话和朗读均通过；一条 68 KB 的回复在打开文字卡片时使最低可用内存
降到 12.5 KB。因此文字在每个环节各设一个硬上限（见[架构](architecture.zh_CN.md#有上限的内容交付)）：
默认的 Hermes system 提示要求回答控制在 300 字以内，设备对提问和回复各最多缓存
8000 字节，与网关的朗读文字上限一致。这项改动、140 字上限和清空草稿的实机验收为 NOT RUN。

审查 issue #3 的修复：转写结果到达后才被接受的取消会保留此前草稿（取消检查、草稿替换
和结束录音阶段在同一临界区）；每条消息保存自己的 system 提示，重试时重复原请求
（结构 v5，不做迁移）；仍处于 `creating` 的会话可以连同未发出的首条消息一起删除；
网关最多保留 16 条转写。服务端测试和固件宿主测试分别覆盖；固件改动的实机验收为 NOT RUN。

审查 issue #4 的修复：网页在开始发送时清空输入框，响应回来后不再改动，等待期间输入的
文字得以保留（发送失败时把原文放回）；重连时即使状态相同，只要修订号变了就重新读取回复；
其他客户端用同一 ID 重试最新消息时，设备会重新读取这一轮；需要重新合成的朗读续传返回
409 并结束播放。移除了对话窗口、`/api/v1/ping` 和固件中无人调用的命令，发现广播改为
协议 2，本轮轮询只读元数据。`tools/test-web.mjs` 在 Node 中运行网页回归测试。并发准备
转写有意不加上限：同一时间只有一台设备在准备。固件改动的实机验收为 NOT RUN。

进入会话后先显示语音优先界面（圆点、状态行、单行文字条和按键提示），文字卡片作为
第二个界面，详见固件指南。网关在回复完成后用一次 OpenAI Realtime 请求合成整条回复，
以分帧的 16 kHz PCM 流式下发；设备通过与录音共用的缓冲播放，连接中断后按字节偏移
续接。设备不再订阅 SSE：Hermes 写回复期间每秒轮询一次本轮状态，完成后取回完整回复；
网页聊天仍使用 SSE。设备在 RTC 内存中保留诊断记录并在故障后上报，网关负责保存与
展示。服务端测试、固件宿主测试和宿主界面预览覆盖本迭代。固件 `e1bc3c5` 已于
2026-11-15 刷入并实测（见固件指南）；最新构建上语音界面与朗读的实机验收需要单独的
证据。

## 完整消息迭代

已确定的设备模型是在 RAM 中保存一条完整用户输入和一条完整 Hermes 回复。
Go 返回完整消息正文及相邻消息 ID，访问历史时按需加载另一轮完整提问／回复。
消息显示在可本地上下滚动的卡片中。SSE 在后台追加缓存回复，卡片在整个生成
过程中显示状态图案与动画。回复完成后从开头显示全文，由上下键控制阅读位置。
标题、时间与电量合并为顶部单行，角色和状态共用卡片首行。等待时可以查看自己的
输入，回复失败或中断时展示已保留的正文及结果提示。

SSE 恢复先建立订阅，再读取完整快照。通过初始 `resync`、字节偏移去重、缺口检测
及 `chat.reset` 核对完整消息缓存。由服务器计算固定屏幕卡片的配置已退役。
当前消息缓存和设备事件流需要在新固件上进行内存与交互测量。

## 实现中需要确定的事项

- 在设备上同时测量当前 PCM16/HTTP 采集、完整消息 RAM 增长及朗读播放。
- 根据设备验收完善草稿编辑粒度及已实现的实体按键映射。
- 根据设备验证已实现的接口上限和会话分页大小。
- 验证历史／会话切换时的缓存释放，并测量代表性完整消息的空闲堆、最大连续块及栈余量。
- 待审批操作和不可显示媒体的呈现方式。
- 使用提供的凭据验证模型权限、延迟和识别准确性。
