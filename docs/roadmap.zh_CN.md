# 里程碑

## 当前迭代

已确定的设备模型是在 RAM 中保存一条完整用户输入和一条完整 Hermes 回复。
Go 返回完整消息正文及相邻消息 ID，访问历史时按需加载另一轮完整提问／回复。
消息显示在可本地上下滚动的卡片中。SSE 在后台追加缓存回复，卡片在整个生成
过程中显示状态图案与动画。回复完成后从开头显示全文，由上下键控制阅读位置。
标题、时间与电量合并为顶部单行，角色和状态共用卡片首行。等待时可以查看自己的
输入，回复失败或中断时展示已保留的正文及结果提示。

SSE 恢复先建立订阅，再读取完整快照。通过初始 `resync`、字节偏移去重、缺口检测
及 `chat.reset` 核对完整消息缓存。由服务器计算固定屏幕卡片的配置已退役。
当前消息缓存和设备事件流需要在新固件上进行内存与交互测量。

## 实现中需要确定的事项

- 在设备上同时测量当前 PCM16/HTTP 采集、完整消息 RAM 增长及 SSE 恢复。
- 根据设备验收完善草稿编辑粒度及已实现的实体按键映射。
- 根据设备验证已实现的接口上限和会话分页大小。
- 验证历史／会话切换时的缓存释放，并测量代表性完整消息的空闲堆、最大连续块及栈余量。
- 待审批操作和不可显示媒体的呈现方式。
- 使用提供的凭据验证模型权限、延迟和识别准确性。
