# AI Passport 固件

首版设备客户端位于 `firmware/`，面向 AI Passport 的 ESP32-C3、8 MiB Flash、
240×320 圆角屏、三个 ADC 按键与 ES8311 音频通路。复用了 voice-memo 的板级支持、
中文字体、设置、Wi-Fi 与 BLUFI 生命周期、即时短按判定及熄屏策略。
现有 memo 项目仍作为硬件参考。

## 语音优先的会话与语音回复

进入会话后显示语音界面：一个圆点、一行状态、一行文字条和两个按键提示。录音也在同一
界面进行：计时占据状态行，文字条显示实时转写的最后十个字。松开后文字条转圈等待最终
结果（这一刻不响应任何按键），随后展开成草稿栏，栏头显示草稿字数和 140 字上限
（达到 90% 时变红）。发送后草稿栏收回成一行显示刚发出的
问题；Hermes 思考时，光弧绕圆点旋转，三根条依次起伏，状态行显示已等待的秒数，直到 Hermes
写完（设备一次取回全文）；若 Hermes 上报 `attention`，状态行显示“等待审批”，设备继续轮询
并在恢复前禁止在该会话中发起新的录音或发送。思考和朗读期间，文字条变成无边框的灰色平底、以灰字显示刚才的问题，表示已发送、处理中
不可更改，与空闲时带边框的文字条区分开；朗读时状态行显示“正在朗读”和已播放的时长
（如 0:23；总时长事先未知，因此不显示进度）；
读完或停止朗读后，文字条从第一行开始变为逐行上滚的字幕：去掉 Markdown 标记，每句
另起一行，超过一行宽的长句接续到下一行，收尾标点不放在行首。每行按每字 220 ms 停留
（1.8–5 秒），下一行用 0.25 秒从下方滑入；最后一行之后停 3 秒再从头开始。上下键停住并
逐行切换，状态行显示位置，15 秒无操作后恢复自动上滚。提示信息替换状态行，不再
浮在其他元素上。文字卡片即原来的对话页，回复完成后显示全文，朗读时状态显示
“正在朗读”。Hermes 写回复期间，设备每秒只查询一次本轮状态（不使用 SSE），完成后一次下载全文。标题下方两个小点区分两种界面。

服务端报告 `speech` 时，设备朗读当前会话每一个新出现的最新一轮回复，无论消息来自设备
还是网页；打开会话不会重播上一轮回复。`agent_speech.c` 读取 `/messages/{id}/speech`
（标记朗读开始的帧、16 kHz PCM，Hermes 思考期间每 5 秒一个保活帧），按录音相同的格式写入
ES8311，并发布是否正在发声、供圆点动画使用的响度以及已播放的时长。开始录音前先停止朗读；已经出声时两种界面下长按下键
都会停止朗读（回复仍在准备、尚未出声时，长按下键直接离开会话）；离开会话也会停止。I2S DMA 环形缓冲只有 90 ms，因此播放分为两段：读取
任务把 HTTP 读到的音频直接写入 16 KiB 缓冲（约 512 ms），这块缓冲与录音共用
（`agent_pcm_pool.c`；开始录音即结束朗读，两者不会同时运行）；写入任务以录音任务相同的
优先级送入编解码器，先预缓冲 400 ms，断流后补足 200 ms 再继续，断流前后各有短暂淡出淡入，
避免爆音。网关下发的朗读音频已针对喇叭处理过（高通与限幅，见服务器指南）。朗读流的速度由这块缓冲限制，播放追上之前 TCP 窗口内的数据一直占着 Wi-Fi 接收缓冲：
固件保留 12 个动态接收缓冲、A-MPDU 窗口 6、8 个报文段（11520 字节）的 TCP 窗口并开启 SACK。
原先只有 6 个缓冲和 4 个报文段的窗口，会丢帧，每次丢包都要在网关上等 0.24–0.54 秒的重传超时，
比缓冲能撑的时间更长（2026 年 11 月实测）。连接断开后携响应头 `X-Speech-Stream` 提供的流标识从停下的那个字节续接（`?offset=<字节数>&stream=<流 ID>`，最多 3 次，保活帧不计入），帧解析
状态跨连接保留。如果网关需要重新合成这条流（返回 409 `speech_restarted`），朗读就此结束，
不会接着播放重新合成的音频。朗读诊断事件记录断流次数、最长网络空档和续播次数；朗读期间关闭 Wi-Fi
省电休眠，断线原因也会记录。缓冲和写入任务在开机时一次性预留：之前每次回复临时分配，
造成堆碎片化（一次朗读后最大连续块从 59 KiB 降到 35 KiB，最低空闲堆降到 26.7 KiB）。

静止时的逐行字幕只绘制一行静止文字，仅在换行时播放 0.25 秒的滑动动画，渲染开销
极小。圆点位于模式小点下方 8 像素处，思考光弧不会碰到
顶部栏。有草稿时长按下键在本地清空草稿，不发送任何请求。

## 诊断报告

固件在 RTC 内存中保留诊断记录（`agent_trace.c`）：最近 160 条事件和约 1.5 KiB
警告／错误日志，共 5.3 KiB。软件重启、崩溃和看门狗复位后仍保留，上电时清空。
事件包括按键按下／松开、带页面与录音状态的手势判定、页面和录音状态切换（附内存
数据）、修改类 HTTP 请求与失败的读取（状态码和耗时，不含 ID 与请求体）、音频上传
结果、录音结果标志、发送请求以及采音错误。例行成功的轮询不记录，以免冲掉上下文。

录音失败、采音出错、异常复位（崩溃、看门狗、掉电、锁死）或录音失败后 5 秒内发送
草稿时，设备向 `POST /api/v1/device/logs` 上报。网络任务在录音空闲时上传，每 15 秒
最多一次、每次启动最多 30 次；上传失败会保留待下次重试。上传时从 5.3 KiB 的堆上
快照以分块 JSON 流式发送，快照只在请求期间占用。报告不含音频、转写文字或凭据。

## 跟随其他客户端的消息

对话页显示最新一轮且回复已结束时，同步任务每 3 秒读取一次会话最新一轮的元数据。
网页（或其他客户端）发出更新的消息后，设备切换到这一轮，按上文方式等待回复并朗读。
最新消息仍是当前这条、但状态或修订号变了（其他客户端用同一 ID 重试）时，设备重新读取
这一轮；其他客户端重试的结果不会再次朗读，在设备上重试的会朗读。正在翻看较早的对话时不会被打断。

| --- | --- | --- |
| 会话列表 | 上下选择，越过页边界后加载另外四条会话。OK 进入选中会话。 | OK 打开本地新对话并持续录音（首次发送时网关才创建会话），上键循环切换一级页面，下键休眠。 |

| 文字卡片 | 上下键每次滚动约 70% 的可视区域（按整行对齐）。到达边缘时双击同一方向键（0.5 秒内第二次按下，第一次按下会提示）切到上一条或下一条（提问／回复，再到相邻历史对话），新消息总是从顶部开始；已到第一条或最后一条时给出提示。状态栏显示所在轮次，例如“第 3/7 轮”。OK 回到语音界面并显示最新一轮。 | OK 录音。下键先停止正在发声的朗读，否则返回会话列表。 |
| 录音 | 松开 OK 结束。录音中和转写中都不提供取消。 | 持续按住 OK 录音。 |
| 设置 | 上下选择，OK 进入编辑或保存。数值编辑时上键增加、下键减少。 | 在设置列表中，上键循环切换一级页面，下键休眠。在属性编辑中，下键取消未保存的修改并返回设置。 |
| 配网 | OK 结束配网并恢复正常联网。 | 下键结束配网并返回设置。 |

对话页直接显示待发送文字供检查。草稿只保存在设备 RAM 中（协议 2，2026-11-16）：
转写是中转服务的旁路，只返回最终文字，不保存任何内容。短按 OK 发送当前显示的文字并
带上草稿序号，之后的新录音或清空会使仍在队列中的发送失效。长按 OK 重录：转写成功
则替换草稿；取消、没有听清、超过 140 字或上传失败都保留此前文字。离开会话即丢弃
草稿。未发送草稿不推迟休眠，深度睡眠或重启会丢失草稿。设备缓存的
提问和回复各以 8000 字节为上限，与网关的朗读文字上限一致，显示和朗读的是同一段。
超出部分保留在服务端，设备按 UTF-8 边界保留开头，并提示只显示开头、完整内容请在网页查看。会话列表与设置登记在同一份
一级页面列表中，长按上键依次切换并循环，新增一级页面沿用同一注册方式。一级页面
长按下键休眠，详情中长按下键逐层退出。手动休眠先暂停联网，并等待按键松开。
重新发现服务器可在设置的服务器选项中按 OK。每次短按独立响应，按键驱动的
多击事件不触发额外动作。

设置包括网络、服务器、音量、亮度、熄屏时间、深度休眠时间、主题、时区与版本。深度休眠从熄屏后
开始计时；录音、Hermes 思考和朗读回复期间屏幕保持点亮。选中会话标题横向滚动，日期和未选中项采用有边界的单行布局。页面拥有自己
的控件和动画，切页时先载入固定过渡屏，再删除离开的页面。

会话列表来自 Go 管理的索引。在会话列表长按 OK 会打开一个只有本地会话 ID、名为
“新会话”的新对话；第一次发送前中转服务上什么都没有，第一次发送才创建会话，并返回
中转服务根据发出的文字生成的标题。因此放弃的录音不会留下空会话。内部 ID 保存在
协议字段中。
2026-11-14 用户授权删除的两条旧测试会话已完成本机与 Hermes 同步清理，旧标题
后缀处理和 v1 数据库迁移已移除。

## 音频与内存

录音通过分块 HTTP 向 Go 上传 16 kHz 单声道 PCM16。Go 持有 OpenAI 转写、上游
凭据与 TLS/WebSocket 连接。设备保留与朗读播放共用的 16 KiB PCM 缓冲、各四条
会话元数据、512 字节实时转写预览，以及按实际大小分配的草稿（140 字最多 560 字节）。

当前选中对话在 RAM 中拥有一条完整用户输入和一条完整 Hermes 回复，按实际字节
长度动态申请。切换历史时加载另一整轮对话，释放上一轮缓存。消息由服务端持久化。
可见 LVGL 标签拥有独立的字形过滤显示快照，在 LVGL 锁内替换和释放；先释放旧快照再拷贝
新内容，回复不会在缓存之外同时存两份。语音页的逐行文本在一份拷贝上原地生成，并截到
文字条能翻到的 256 行（约 7.5 KiB）；问题条只在静态缓冲中保留提问的
前 255 字节。新快照分配失败时
标签保持为空，并在提示行报告内存不足。启动蓝牙配网前释放消息缓存。

设备不使用 SSE。回复生成期间，同步任务每秒只读取一次本轮元数据；状态结束后一次
读取完整回复。卡片背景色未变化时不重复设置，避免静止消息被持续重绘。传输连续失败时
使发现端点失效，重新查找网关。

完整消息在本地滚动。顶部包含返回箭头、居中截断的单行标题，以及时间和电量。
助手生成期间持续显示轻量转动的圆弧。回复完成后从开头显示整条正文，
由上下键控制阅读位置。等待时上键可切换到用户输入。失败或中断时显示已保留的
文字和结果提示。草稿发送和等待回复使用各自的状态提示。

设备要求网关协议 2，并依赖 `bounded_paging`、`text_tail` 和 `whole_messages`；
网关报告 `speech` 时使用朗读功能。服务发现仍使用
`_voiceagent._tcp.local`，蓝牙广播名为 `BLUFI_AGENT`。Go 启用设备凭据后，
可通过 `CONFIG_AGENT_API_KEY` 配置。

## 构建与验证

激活 ESP-IDF 5.5.3 后，在仓库根目录运行。

```sh
./tools/validate.sh --static
./tools/validate.sh --firmware
# 两个阶段一起运行

```

固件检查从已跟踪默认配置生成独立配置，构建并合并镜像，验证分区与镜像布局，将匹配
的 ELF、MAP、分段镜像及 `flash_args` 归档至 `build/firmware/<完整镜像sha256>/`。
验证后的合并镜像为 `build/Voice-Agent-Terminal-full.bin`。宿主测试覆盖 JSON 限值、
UTF-8、四条分页、连续短按、长按抬起抑制、设置持久化和空闲计时，字形检查覆盖固定
中文界面文案。动态内容中超出中文字库的字符显示为 `?`。

分区使用 `0x9000` 的 NVS（24 KiB）、`0xF000` 的 PHY（4 KiB）及 `0x10000` 开始占用
剩余 Flash 的 factory 应用。迁移设备前，需先在原固件中完成待传 voice-memo 录音的
上传。分段刷入按记录偏移写入 bootloader、分区表和应用，Wi-Fi 与设置沿用既有 NVS
位置。合并镜像从 `0x0` 写入，填充区可能重置 NVS/PHY。刷入需要对具体验证构建及其
数据影响获得授权。
