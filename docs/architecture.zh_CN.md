# 架构

## 已确定的边界

手持设备通过 mDNS 发现并连接 Go 中转服务。Go 对接 Hermes 已有 API 和
OpenAI 转写服务。上游凭据和 TLS 连接由 Go 服务持有。

首版聊天采用 Hermes `POST /v1/chat/completions`，通过
`X-Hermes-Session-Id` 续接会话并接收流式回复。Go 使用 Hermes 已有会话
API 协调创建、列表和删除。依赖这些行为之前，需要针对选定的 Hermes 版本验证。

## 数据归属

| 归属 | 数据与职责 |
| --- | --- |
| 设备 | 选中的会话、已审阅草稿版本、RAM 中的一条完整用户输入和一条完整 Hermes 回复、本地阅读位置、有界音频传输缓冲及交互状态 |
| Go | 设备与 Hermes 会话映射、分页会话索引、持久化草稿和段落顺序、完整消息快照及重试标识、有界 SSE 投递与过滤后的回复存储 |
| Hermes | 对话历史、模型上下文、会话运行状态和配置的 Agent 能力 |
| OpenAI | 转写 Go 提交的音频 |

Go 的会话索引为设备提供 Hermes 会话视图。创建和删除具有持久化的待处理状态，
用于操作中断后的恢复。Go 保留设备索引，并将创建及修改的标题转发至 Hermes。
设备在 RAM 中保存当前选中的完整输入与回复。访问历史时，通过消息 ID 和相邻消息
ID 选择另一轮完整提问／回复。完整正文响应保留已保存的 UTF-8 内容及版本标识。

## 消息阅读与等待

消息在加载、流式接收和阅读过程中保持同一个对象。选中的消息显示在可本地上下滚动
的卡片中，上下键在完整正文缓存内移动阅读位置。用户请求历史时加载另一轮完整
提问／回复。RAM 按当前文字的实际大小分配，退出对话时释放缓存。会话列表继续按
列表条目分页。

Hermes 回复通过 SSE 写入设备缓存。生成期间，卡片持续显示状态图案与动画。
回复完成后，从开头显示整条正文，由上下键控制本地阅读位置。等待时可查看自己的
输入。顶部单行容纳页面标题、时间及电量，角色和状态共用卡片首行。回复中断或
失败时，展示已保留的文字及对应结果提示。

固件 `9b06632b` 已按授权刷入，启动、服务发现及一次录音／回复工作负载通过。
用户确认 SSE 追加改善、中文引号正常。后续 `077092ec` 已获用户确认，顶部栏／
状态布局、卡片间距、等待完成、回复从开头显示与手动滚动均通过。长消息压力及
断线恢复仍需单独检查，内存测量与交互结果对应各自记录的构建。

## 草稿组织

每次录音创建具有顺序位置和代次的段落 ID。草稿处于可编辑状态时，实时识别
更新对应段落。中转接口支持继续录音追加及删除选中的段落。
当前设备交互在对话中审阅待发送消息，短按 OK 发送，长按 OK 重录。替换录音保留
此前文字，直到非空最终转写原子地将其退役。完整草稿读取与发送快照使用相同的
拼接规则和版本。

编辑和转写更新都会推进草稿版本。删除会结束段落的生命周期，迟到更新按段落
ID、代次和有效状态检查。发送请求携带用户已经审阅的版本。Go 校验版本，
并原子地将对应文字固定为消息快照。版本过期时，返回当前草稿供用户审阅后重新发送。

版本校验保证识别结果迟到时仍能保留用户所见的发送内容。明确发送是向 Hermes
提交草稿的唯一触发动作。消息提交后内容固定。草稿和发送失败恢复应保留用户输入
及对应操作标识。

录音结果先暂存，由设备自动确认后替换旧稿。取消、重启和未确认结果过期时清理
暂存，旧稿继续可用。提交与取消通过事务及持久化提交版本对账。文本读取请求的
代数隔离晚到响应，服务发现拒绝候选后轮换地址。

## 音频与转写

目标是边录音边上传，并在录音过程中显示转写。Go 持有 OpenAI 实时连接，
将选定的设备音频格式转换为上游接受的格式，并把事件关联到对应录音段落。
结束录音后，提交本段音频，将转写结果落实到草稿。识别完成和发送消息是分别
呈现给用户的两个状态转换。

首个候选模型为 `gpt-live-transcribe`。2026-11-13 查阅的官方实时转写
示例使用 24 kHz 单声道 PCM16，并明确提交每段音频。模型权限、可接受格式
和延迟需要真实录音验证。按上游条目标识和段落代次匹配事件。

设备通过分块 HTTP 上传 16 kHz 单声道 PCM16，需要连接 Go 服务器。
音频缓冲为 8 KiB，录音期间使用有界实时转写预览，确认后的输入以完整正文读取并
审阅。新的完整消息修订仍待实机验收，状态为 NOT RUN。在 AI Passport 上同时
测试采集与联网，记录总空闲堆、最大连续块、任务栈高水位和有界背压行为。
当前 voice-memo 的录音与上传生命周期提供实现参考。

## 聊天与恢复

Go 将已固定的文本快照提交给映射的 Hermes 会话。在提交前持久化消息标识，
同一次发送的精确重试复用上游幂等键。同一会话串行发送，保证顺序清晰。
选定 Hermes 运行模式的去重与续接行为需要直接测试。

Go 跟踪发送中、等待、接收中、完成、未完成、失败和结果未确认等状态。
保留上游结束原因，连接中断后向设备呈现明确状态。重新连接时，基于缓存输出
或上游状态对同一消息进行核对。运行任务、重试依据和回复投递分别管理生命周期。

设备恢复时，先建立会话 SSE 订阅，再读取完整消息快照。初始 `resync` 事件触发
元数据及完整正文读取，返回正文的 UTF-8 字节长度建立增量基线。`chat.delta` 按
匹配的字节偏移追加到同一条回复，已被快照覆盖的偏移去重；偏移不连续或收到
`chat.reset` 时读取新的完整快照。正文响应头中的版本与状态属于同一次持久化读取。
断线恢复重新加载该完整消息，再核对后续 SSE 事件。

## 有上限的内容交付

Go 增量解析上游 SSE 与 JSON，明确限制事件、字段、待判定前缀和回复缓存大小。
媒体标记和 base64 内容可能横跨多个分片。过滤过程应保留后续文字与有效 UTF-8。
省略的媒体以简短资源说明表示。通过完整消息正文及有界增量事件交付文字，传输
事件上限与 RAM 分配检查保持逻辑消息标识及完整的已保存正文。

审批事件、推理内容和进度分别制定呈现策略。首版设备功能聚焦文字聊天。
待审批操作保留等待状态，并产生简短的待处理提示，详细审批交互仍是开放的产品决策。

## 发现与设备接口

mDNS 记录指向 Go 服务并声明协议版本。Go 的能力响应说明可用的聊天、草稿
和转写功能。已实现的服务类型、路由、负载上限和恢复语义见
[服务端接口](server.zh_CN.md)。

服务端支持 HTTP PCM16 音频上传与有界 SSE 事件，音频上传与回复投递分别流控。
设备读取完整消息快照，并将回复事件追加到选中的 RAM 缓存。元数据轮询支持发现与
录音状态。本次修订的设备内存和延迟仍需实测，OpenAI 实时传输由 Go 承担。
